JavaScript 3: control flow, loops, objects, references

One finger, one line at a time. That finger can skip, it can go round in circles, and it can be handed the same object under two different names. The last one is where "but I never touched that" bugs are born.

LAST TIME

A function is a recipe: writing it does nothing, calling it runs it. return hands a value back and stops the function on the spot, which is what makes guard clauses work. The call stack is a pile of index cards, one per function in progress, and only the top card is running.

Quick check

A function does its job but printing its result gives undefined. What is wrong?
Nothing is broken. It has no return, so the caller gets the machine's shrug. You never said what to hand back.
const goal = { days: 30 }; then goal.days = 60;. Legal or not?
Legal. const locks the name tag, not the object behind it. Only goal = somethingElse is refused. Today is the chapter where that distinction starts costing money.
Why does Memento's CLAUDE.md ban git add -A?
Two agents work in one tree. A blanket add scoops up somebody else's half-finished work into your commit. You add your own files by name.

The idea

Chapter 1 gave you an intern reading a to-do list top to bottom. Everything in this chapter is a way of moving that intern's finger somewhere other than the next line down.

There are only three moves, and every program ever written is made of them. Go to the next line. Skip some lines. Go back and do some lines again. That is it. Control flow is the name for which line the finger is on and where it goes next.

if / else: skip some lines

An if statement asks a yes-or-no question and runs its block only when the answer is yes. An else block is what runs when it is no. The finger takes one path or the other, never both, and then both paths rejoin at the line after.

if (streak > 7) {
  showBadge();          // only when the answer is yes
} else {
  showEncouragement();  // only when the answer is no
}
console.log("both paths get here");

The question inside the brackets does not have to be a true or false. JavaScript will accept any value and decide for itself. A value that counts as yes is called truthy; one that counts as no is falsy. There are exactly six falsy values worth memorising: false, 0, "" (empty text), null, undefined, and NaN. Everything else is truthy, including the empty array [] and the empty object {}, which trips up nearly everyone the first time.

That is why chapter 10's guard clause read if (!text || aiChatLoading) return; instead of comparing anything. !text means "text is falsy", which covers empty, never-set, and deliberately-empty in one character.

Loops: go back and do it again

A loop repeats a block. The single most important thing to hold in your head is this: a loop does not run all at once. It runs its block, finishes it completely, then starts the block again from the top. One pass of the finger, then another. Ten items means ten separate passes, in order, one after the other. Nothing in a loop is simultaneous.

Three spellings cover everything you will read in Memento.

SpellingReads asUse when
for (let i = 0; i < 5; i++)"start at 0, keep going while under 5, add one each pass"You need the position number.
for (const item of list)"for each thing in this list, one at a time"You just want the items. The common case.
while (condition)"keep going as long as this stays true"You do not know how many passes there will be.

The classic for has three parts separated by semicolons: where to start, when to keep going, what to change each pass. Chapter 1's sandbox 5 forgot the third part, so the condition never changed and the finger went round forever. That is the ordinary failure, not an exotic one.

Arrays and the five methods you will actually read

An array is an ordered list. Its positions are numbered from zero, not one, so list[0] is the first item, and list.length is how many there are. Loops and arrays go together so often that the language ships with shortcuts: methods that run a small function once per item and hand you something back.

MethodWhat it hands back
push(x)Nothing useful. It adds x to the end of the array itself.
filter(fn)A new array holding only the items where your function said true.
map(fn)A new array, same length, each item replaced by whatever your function returned.
find(fn)The first item where your function said true, or undefined if there is none.
forEach(fn)Nothing. It runs your function once per item for the side effect.

The function you hand over is chapter 10's arrow function, and the ones that hand back a new array can be chained. Reading a chain out loud, left to right, is how you decode the dense Memento lines below.

The object trap

Now the part that is worth the whole chapter.

Chapter 9 said assignment copies the value and the two names are then independent. True for numbers, text and booleans. For objects and arrays it is a trap, because the value a name points at is not the object. It is a reference: an address of where the object lives in memory. Copying an address gives you a second piece of paper with the same address on it. Both lead to one house.

ANALOGY (TEMPORARY)

A shared Google Doc. const backup = state is not printing the document. It is sending someone the link. Now two people have their own link, but there is still one document. When the other person deletes a paragraph, your link shows the deletion, because your link was never a copy of anything. {...state} is File, Make a copy: a real second document that now drifts apart from the first.

Two names for one object is called aliasing, and it is not a flaw. It is why Memento's 38 files can all say state and all mean the same live object. It becomes a bug only when a human believed they had made a copy and had not.

The cheap fix is the spread: const copy = {...original} builds a genuinely new object and copies each key across. For arrays it is [...list]. One catch, and it has a name: this is a shallow copy. The top level is new, but a nested object inside is still copied as an address, so both still share everything one level down.

And the third misconception, the one chapter 9 planted deliberately: const does not freeze contents. It only refuses to let the name be re-pointed. const list = [] then list.push("a") is legal all day long, because the array is the same array. It just has something in it now.

try / catch: if this line explodes, do this instead

Some lines fail for reasons that have nothing to do with your code being right. The disk is full. A private window blocked storage. The text handed to you is not valid JSON. When a line fails like that it throws, and by default the throw kills everything up the call stack until the app stops.

try / catch puts a net under a block. Run these lines. If any throws, abandon the rest of the block, run the catch block instead, then carry on. It is a human deciding in advance what "keep going anyway" looks like at that exact spot.

Now in Memento

ANY APP: saving without dying

Writing to the browser's storage box can fail for reasons no developer controls: the box is full, or a private window refused it. If a failed save crashes the app, the user loses the thing they were typing plus everything else. So each risky step gets its own net, and a failure in one does not cancel the others.

Then, occasionally, keep a copy of the previous save under a second name. If the newest save is ever written half-broken, yesterday's copy is still sitting there.

Read it as control flow and it decodes in about thirty seconds.

The first try is the backup. if (now - _lastBackupAt > 30000) means "has it been thirty seconds", so the block skips itself almost every time. if (prev) is a truthiness check: only copy the previous save if there was one. The catch (e) {} is an empty net on purpose, because a failed backup must never stop a real save.

The second try is the real save, and its catch is not empty. It asks what kind of failure this was: e.name === 'QuotaExceededError' || e.code === 22 means "storage is full", written two ways because different browsers report it differently. Then if (quota && !_quotaWarned) shows the warning once and only once, because a toast on every keystroke would be worse than the bug. Two conditions, two truthiness checks, one flag flipped so the second pass takes the other path.

ANY APP: reading a list of events

Apps keep a log of what happened: a flat list of small objects with a type and a date. Questions about the user get answered by narrowing that list, then pulling out the one field you care about. Narrow first, then transform. That is filter, then map.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

The alternative to wrapping each step in its own try is one big try around the whole function. Shorter, and wrong here: a failed backup would abandon the real save, so a rare thirty-second housekeeping job could silently cost a user their actual data. Separate nets mean the important line still runs. The cost is that empty catch (e) {} blocks hide failures completely, and a genuine bug inside one of them is invisible forever. Memento accepts that on the backup and refuses it on the save, which is why only the second catch inspects what went wrong. Chapter 23 comes back to swallowed errors as a debugging problem.

WORDS YOU NOW OWN
Control flow
Which line the machine is on and where it goes next. Three moves only: next line, skip lines, go back.
if / else
Take one path or the other, never both, then rejoin.
Truthy / falsy
What a non-boolean counts as in a yes-or-no question. Six things are falsy: false, 0, "", null, undefined, NaN. Empty arrays and empty objects are truthy.
Loop
Run a block, finish it, run it again. Passes in order, never all at once.
for / for...of / while
Counted passes / one pass per item in a list / keep going while something stays true.
filter / map / find / forEach / push
Keep some / change each / get the first match / do something per item / add to the end. The first three hand back something new; the last two do not.
Reference
What a name actually holds when the value is an object: an address, not the object. Assignment copies the address.
Aliasing
Two names for one object. Deliberate almost everywhere in Memento, a bug the moment somebody thought it was a copy.
Spread
{...obj} or [...list]. Builds a genuinely new top level.
Shallow copy
A copy whose nested objects are still shared with the original. What spread gives you.
throw
A line giving up and killing everything above it on the stack until something catches it.
try / catch
A net under a block. If anything in try throws, abandon the rest of the block and run catch instead.
WHERE TODAY'S ANALOGY BREAKS

Breaks when: you ask who is allowed to edit the shared document. Google Docs has permissions, a history, and a name next to every change. Memory has none of that. Any code holding the reference can change the object instantly, with no record of who did it and no way to ask afterwards. That is why the "which line wrote this" bug is so expensive, and why chapter 14 puts every write behind one path. Real model: a variable holding an object holds a number, and that number is an address. Two variables holding the same number are indistinguishable: no original, no copy, no owner, no audit trail. A second, smaller break: the finger does not always stay on one line for long. Chapter 12 shows it walking away from a half-finished function and coming back later.

RABBIT HOLE: what JSON.stringify silently drops

JSON.stringify(state) walks the whole object turning it into one long piece of text, because storage only holds text. Two things get quietly lost. Functions vanish: a key whose value is a function is dropped entirely, no error. And undefined vanishes while null survives, which is one practical reason chapter 9 found paidAt: null rather than undefined. A key set to undefined is there in memory and gone after a save and reload, a bug that only appears to users who close the app.
