Backends: servers, routes, handlers, edge functions

A server is not a machine in a rack, and it is not magic. It is a program that sits awake on an address, and for every parcel that arrives it looks up which function to run. Today you read Memento's real one from line 1, then add a route to your own.

LAST TIME

A client asks and a server answers, in parcels with five parts: a verb, a path, headers, a body, and a three digit status code coming back. JSON is the parcel's language, and an API is the contract that says which parcels an address accepts. You sent four of them by hand with curl.

Quick check

401 and 403 both mean no. What is the difference?
401: I do not know who you are, go and sign in. 403: I know exactly who you are and you still may not do this. Memento's native app turns a 403 into paid-required for that reason.
What is the difference between defining a function and handing it to something else?
Defining writes the recipe. Handing it over gives another program the card, so it can call it later, on its own schedule. That is what an event listener is, and it is what every route in a server is too.
Why does Memento's phone app never talk to Anthropic directly?
Because the call needs a secret key, and anything shipped to a phone or a browser can be read by anyone who has it. So the phone calls a server Memento controls, and that server holds the key.

The idea

Take the word apart. A server is a program that repeats three things forever: it listens on a port, it waits, and when a request arrives it runs a function and writes a response. The program you started with node server.js was a server the moment it printed its line and refused to exit.

The interesting part is the lookup in the middle. A route is a pair: this verb plus this path goes to this function. That function is a handler. The code that reads the verb and path and picks the handler is a router. That is the architecture of every backend ever written, from ten lines to ten million.

ANALOGY (TEMPORARY)

A reception desk with a laminated list of extensions. Somebody walks in, says what they want, and the receptionist reads the list: "deliveries, extension 4" or "accounts, extension 9". The receptionist does no actual work. They match what was said against the list and pass it on. Anything not on the list gets the same flat answer: nobody here does that. A route is a line on the laminated list. A handler is whoever picks up at the extension.

Where the server runs is a separate question with three common answers. Rent a whole computer and keep your program running on it, which means you also own patching it, restarting it at 3am, and paying for it while it sits idle. Pay a platform to run a container for you. Or write one file, hand it over, and let the platform start it when a request arrives and stop it when nobody is calling. That last one gets called serverless, a marketing word, because there is obviously still a server. Honest version: a server somebody else keeps warm, started from a file, billed per call.

Memento's version is a Supabase edge function, and it is also a proxy: a server of Memento's own standing between the phone and Anthropic. One file of TypeScript, deployed with one command, run on machines near whoever called. Memento pays per invocation and owns no computer.

Two more words before the real file. The environment is the set of named values the platform hands a program at boot, and it is where secrets live: not in the code, not in git. And a rate limit is a counter that refuses a caller who asks too often, which for an app that spends money per request is the spending cap.

Box 3 is the one worth sitting with. When the thing that counts your calls breaks, there are two choices. Fail open: "the counter is down, let everybody through", which keeps users happy and hands an attacker an unlimited budget on your card. Fail closed: "the counter is down, nobody goes through", which annoys users for a few minutes and cannot be turned into a bill. Memento fails closed, in writing, at the top of its proxy.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

Call Anthropic from the phone. Simplest thing that works, one less moving part, and a key shipped to every user. Memento did this once, and the comment recording it is still in the client: // SECURITY: no API key ships in client code. (A live key used to sit here and / // is in git history; it MUST be revoked, see overnight/AI_PROXY_SETUP.md.) (memento-app/js/03-ai-integration.js:10-11, web pin ca8afc8). That is not a hypothetical. That is the origin story of the file you just read. Run your own server. Full control, any language, no platform limits, and you now own uptime, patching, scaling and a bill that runs whether anyone calls or not. An edge function. One file, one deploy command, billed per call, near the caller, and the platform owns the machine. The cost is real: cold starts, a vendor's runtime, execution limits, and your backend logic living somewhere that is not your main repo's normal flow. For a solo founder with one AI call to protect, that trade is not close.

WORDS YOU NOW OWN
Server
A program that listens on a port, waits, and runs a function for each request. It does not exit.
Listen
Claiming a port and sitting awake on it. Two programs cannot listen on the same port.
Route
A pair: this verb plus this path goes to this function.
Handler
The function a route points at. Takes the request, returns a status and a body.
Router / dispatcher
The code that reads verb and path and picks the handler. Always ends with a fallback 404.
Serverless / edge function
A server somebody else keeps warm, started from one file, billed per call. Memento's backend is a handful of them.
Environment
Named values the platform hands a program at boot. Where secrets live, because they are not in the code and not in git.
Proxy
A server of your own that stands between your app and someone else's API, so the secret, the model choice and the spending cap live on your side.
Rate limit
A counter that refuses callers who ask too often. For a paid API it is a spending cap, not politeness.
Fail closed
When the safety check itself breaks, refuse. The opposite, fail open, turns an outage into an unlimited bill.
Deno / Node
Two ways to run JavaScript outside a browser. Supabase functions use Deno; Memento Jr uses Node.
WHERE TODAY'S ANALOGY BREAKS

Breaks when: you picture one receptionist, at one desk, remembering the morning. An edge function has no desk. Dozens of copies of it can be running at once in different cities, any of them can be shut down the moment it stops being called, and the next request may be answered by a copy that has never run before and remembers nothing. That is why the rate limit counts in a shared database instead of a variable in the file: a variable would be counting one copy's morning, which is worth nothing. It is also why the first call after a quiet spell is slower, a cold start. Real model: a handler is a pure-ish function that receives a request and returns a response, run on a machine that may not exist five seconds later. Every piece of memory that has to outlive one request belongs in a database. Chapter 17 is that database.

CAMEO: Deno vs Node, and why Memento uses both

Both run JavaScript outside a browser, which for most of the language's life was a niche curiosity and since Node in 2009 is ordinary. Node came first and brought npm with it; Memento Jr is Node, which is why its first lines say require("http"). Deno is the newer one, built by the same person, and it runs TypeScript directly with no build step and reads its environment through Deno.env. Supabase's edge functions run on Deno, so Memento's backend is Deno and its practice server is Node. The language is the same. The standard library and the import style differ, which is exactly the kind of difference that makes an AI agent write confidently wrong code if you do not tell it which runtime it is in.
