What happens when you tap a button

One tap in Memento touches your phone, a server in a data centre, an AI company's computers, and a database, and comes back, in about two seconds. This chapter is the map of that trip. Every later chapter zooms into one stop on it.

LAST TIME

A computer is a CPU, memory, and a disk. A program is a file of instructions. The machine runs them literally and never knows what you meant. Your AI agents guess your meaning when they write; the machine does not guess when it runs.

Quick check

What does "7" + 5 print, and why?
"75". The quotes make 7 text. Adding text glues. The machine applied its rule; it did not ask what you meant.
What is the difference between a program and a process?
A program is the file. A process is that file while it is running, loaded into memory with the CPU walking through it.
Why does the 37-line action shim exist?
Eighty places still name a deleted feature. The machine would hit a name pointing at nothing and stop. The shim catches the old name and forwards it.

The idea

Software is not one thing in one place. It is a relay. The tap starts on your phone, and the work gets handed from one computer to the next and back. Here is the whole trip for Memento's most important tap: starting a Clarity interview.

Read it as a story:

  1. Finger, screen. The glass senses the touch. The phone's operating system works out which app, which spot. It hands the app an "event": a tap, here, now.
  2. JavaScript. Memento's code has a function waiting for exactly that event. It runs. It decides: start the interview.
  3. State. The code updates the app's memory of the world. "Interview: loading." The screen is redrawn from that.
  4. The network. The code builds a request, a small parcel of text, and sends it over Wi-Fi or cellular to an address. This is the slow, unreliable part. Everything before this took microseconds. This takes hundreds of milliseconds and can fail.
  5. The edge function. The parcel arrives at a small program Memento wrote, running on a computer rented from Supabase. It checks the parcel, checks you are not spamming, and builds a new parcel for the AI, adding a secret key that only this server has.
  6. Anthropic. Their computers run the model and send text back. Memento pays per call.
  7. Back up. The edge function cleans the reply and sends it to your phone. JavaScript receives it, updates state: "Interview: question one is ready." The screen redraws.
  8. Saved on the phone. A moment later, state is written to the phone's storage, so closing the app loses nothing.
  9. Sync. If you are signed in, a copy of your state is sent to Memento's database so your other devices, and a lost phone, are covered.
ANALOGY (TEMPORARY)

Ordering at a restaurant. You (finger) tell the waiter (JavaScript) what you want. The waiter writes it on the pad (state) and walks it to the kitchen pass (the network). The kitchen (the edge function) checks the order, then hands part of it to a specialist supplier down the street (Anthropic) who has the one ingredient the kitchen is not allowed to keep in-house (the secret key). The plate comes back through the pass to the waiter to you. The pad is kept (saved on the phone). At closing, the day's orders are filed at head office (sync to the database).

The words, now that you have the picture

Everything on the top row is the frontend: the part that runs on the user's device. Everything on the bottom row is the backend: the part that runs on servers the user never sees. A server is a computer somewhere else that answers requests. The database is where saved data lives on the server side. An API is the agreed way two of these programs talk to each other: what to send, what comes back. The network is the wire and radio between, and it is where speed goes to die.

State is the app's current memory of the world. In Memento it is literally one big JavaScript object named state. localStorage is the small box a browser gives each website to keep things between visits. Supabase is the company Memento rents its backend from. The edge function is a proxy: a middleman, and the reason your phone never holds the AI key.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

The alternative is to call Anthropic straight from the phone with the key baked into the app. It is simpler: no server to run, no rent. It is also how a founder's key ends up in a public file and gets used by strangers until the bill arrives. Memento learned this the direct way: a comment at the top of 03-ai-integration.js notes that an old key "is in git history; it MUST be revoked." The proxy exists because of that. It costs a small monthly rent and one extra hop, and it buys a locked box for the key, rate limits, and a server that decides which model and prompt to use so a free user cannot dress up as a paid one.

WHERE TODAY'S ANALOGY BREAKS

Breaks when: you picture one waiter serving one table in order. A phone can have several requests in flight at once, replies can come back out of order, and a reply can arrive after the user has already left the screen, which is a real class of bug Memento guards against (the native code kills a request the moment the signed-in user changes). Also the "kitchen" is not one building: Supabase's edge function, its database, and its auth are separate services that happen to share a bill. Real model: a set of independent processes on different machines exchanging text parcels over an unreliable network, each holding its own state, with no shared clock. Every distributed-systems headache lives in that sentence. You do not need to solve them. You need to know they exist, and that "it worked on my phone" proves nothing about the server.

RABBIT HOLE: how a tap becomes an event

The touchscreen reports a grid of capacitance changes to a tiny controller chip, which works out a point, which the operating system turns into a touch with coordinates, which it delivers to the frontmost app, which (for a web app) the browser matches against the element under that point and dispatches as a "click" event to any listeners registered on it and its ancestors. That last part is why Memento's code calls e.stopPropagation(): without it, the tap would keep travelling up to parent elements that also have listeners. Chapter 13 shows the tree the event travels through.
