The idea

Chapter 1 said a file is a named chunk of bytes on a disk. The working model is that almost everything on a computer is one. Your code, your photos, the settings. Even a folder (engineers say directory) is a kind of file, one whose contents are a list of other files. Folders sit inside folders, and the whole machine is one nest of them starting at a single top called /, said out loud as "root".

A path is the address of a file: the folders you walk through to reach it, joined with slashes.

/Users/malikpeace/Downloads/MEMENTO/memento-app/js/01-state-foundation.js

Read it left to right and you are walking. Top of the disk, into Users, into your account, Downloads, MEMENTO, the web app, js, and there is the file. That is not a picture of the address. That is the address.

ANALOGY (TEMPORARY)

A path is a postal address written backwards: country, city, street, building, flat. The Terminal is you standing in one room of that building, always somewhere. Commands mean "look around this room", "walk to that room", "read me this page". Finder is the same building with the lights on.

Three shortcuts you will see everywhere. ~ is your home folder, /Users/malikpeace, so ~/Downloads is a whole address in one character. . is "the folder I am standing in". .. is "the folder above this one".

A path starting with / or ~ is an absolute path and means the same thing from anywhere. A path starting with a name, like js/01-state-foundation.js, is a relative path and means "from where I am standing right now". Half of all terminal confusion is one of these used where the other was meant.

Files whose name starts with a dot, like .git, are hidden files. Finder does not show them and neither does a plain ls. Not secret, just marked "tooling, not for browsing", and some of the most important things in a codebase live in them.

Open the Terminal

Press cmd and space, type terminal, press return. A window opens with a prompt and a waiting cursor. Nothing runs until you press return.

The Terminal is always standing in a folder. That folder is the working directory, and every relative path is measured from it. When people get lost in a terminal it is nearly always because they forgot where they were standing, so the first command you will ever run is the one that answers that.

Two habits make this feel less hostile. Press tab: type cd Down, hit tab, the shell finishes it. Tab completion is a spellchecker, because if tab will not complete it, the thing does not exist. Press the up arrow to bring back the last command and edit it instead of retyping.

One trap: spaces separate a command from its parts, so a name with a space in it must be quoted. Memento's root holds a launcher called Open Memento (new modular).command, and reading it takes cat "Open Memento (new modular).command". Without the quotes you get an error about four files that do not exist.

Break it: mistype a path

On purpose: stand in MEMENTO and type cd memento-ap, missing the final p.

cd: no such file or directory: memento-ap

Three facts in one line. cd complained. Nothing by that name exists here. The name it tried is quoted back so you can compare it letter by letter with what you meant. Nothing was created, nothing was damaged. Type cd memento-a, press tab, and you are in. That loop, type, read the error literally, fix the letter, run again, is what the work looks like. Engineers do it dozens of times a day.

Opening code in an editor

The Terminal is for walking and peeking. Real reading happens in an editor, a program built for a whole folder of text files. You already have one: the Claude desktop app's code view shows the file an agent touched, with line numbers. Engineers mostly use VS Code or Cursor, both free, and you need neither to finish this book. open -a TextEdit somefile.js puts any file on screen.

Four things an editor gives you that cat cannot:

  • The file tree. The left sidebar is the figure above, live. Clicking a folder is cd, and the shape of an app becomes obvious in ten seconds.
  • Project-wide search. Cmd+Shift+F searches every file at once. Type persistState and you get all 25 places in Memento's web app that call it. That one feature is most of what reading a codebase is.
  • Go to definition. Cmd+click a name to jump to where it was created. Find references does the reverse.
  • Following a path:line link. When an agent, a test or an error says js/01-state-foundation.js:488, that is a file and a line number, and an editor turns it into a click. This book cites Memento the same way.

Now the routine for any codebase you have never seen. Ten minutes, in order: read the README, read the top-level folder names and guess each one's job, find the entry file that starts everything (index.html, index.js, main.ts, src/app/), read package.json's scripts and dependencies, open the biggest file because that is where the mess lives, find the tests folder because it is the closest thing to a spec, then search one feature name and read what comes back.

See it

A path is text with slashes in it, and the commands you just learned are string operations with a disk behind them. This one runs on your phone.

const p = "/Users/malikpeace/Downloads/MEMENTO/memento-app/js/01-state-foundation.js"; const parts = p.split("/"); console.log("steps in the walk:", parts.length - 1); console.log("the file:", parts[parts.length - 1]); console.log("the folder it sits in:", parts.slice(0, -1).join("/")); function up(path) { return path.split("/").slice(0, -1).join("/"); } console.log("cd .. once:", up("/Users/malikpeace/Downloads/MEMENTO")); console.log("cd .. twice:", up(up("/Users/malikpeace/Downloads/MEMENTO"))); function join(...bits) { return bits.join("/").replace(/\/+/g, "/"); } console.log("joined:", join("/Users/malikpeace", "Downloads/", "MEMENTO")); const HOME = "/Users/malikpeace"; console.log("what the shell does with ~:", "~/Downloads/MEMENTO".replace("~", HOME));

That last line is the whole mystery of ~: the shell swaps in your home folder before the command runs.

Now in Memento

ANY APP

Two ways to organise a codebase.

By load order. Files are numbered and run top to bottom. The number is the architecture. No build step, edit and refresh. But nothing states what needs what, and a file in the wrong position crashes at boot.

By job. Files sit in folders named after what they do, each declaring what it needs, and a tool works out the order. You have to keep that tool. In exchange the dependencies are written down and the folder name tells a newcomer where to look.

MEMENTO

Memento is both, in one folder, because one is being rebuilt into the other. ls memento-app/js gives 38 files, all numbered:

00-backup-security.js
00-error-reporting.js
01-state-foundation.js
02-clarity-experience.js
03-ai-integration.js

The numbers are not decoration. The shell that loads them says so:

<!-- App, split into per-feature files. Loaded as classic <script>s (NOT modules)
     so they share one global lexical scope exactly like the original single IIFE.
     const/let/class stay scoped (no window pollution); top-level function decls
     are hoisted across files at call time. Order matters: every definition file
     must load before 11-init.js, which runs the bootstrap immediately on load. -->
memento-app/index.html:809-813 (web pin ca8afc8)

And the rule for humans, at the top of the repo:

## WHERE THINGS LIVE (edit the right file)
Styling:
- A feature's look → `css/<feature>.css` (Notes look → `css/notes.css`; also dashboard, sidebar, misc, vivere, onboarding, clarity, action).
CLAUDE.md:14-16 (repo root, native pin 93bfa796)

It then lists the js folder file by file so an agent knows which one to open. That list has drifted: CLAUDE.md says 21 js files and 16 css files, ls says 38 and 22. The folder is the truth. A map is a document somebody has to maintain.

Now ls memento-native/src, the rebuild:

ai      auth    clarity  home   rules    sample   storage  ui
app     billing entry    notes  rewards  runtime  star     sync

Sixteen folders, no numbers, named after jobs. Nothing loads by position; each file names what it needs.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

The web app could have used modules and a bundler from day one, which is what almost every team does. Not doing it was right for what it was: one founder and an agent shipping several times a day, where a build step is one more thing that breaks at 2am. The bill arrived later. 67,000 lines in one shared global scope, a file numbered 33 that exists to catch a deleted name, two files numbered 20, a map that no longer matches the folder. The rebuild pays the tooling cost up front to get the import graph back. Chapter 26 adds up what each one cost.

NEVER TYPE THESE INSIDE ~/Downloads/MEMENTO

Everything above only reads. These change things, and this folder is a live product two agents work in.

  • rm deletes, with no Trash and no undo. rm -rf takes a whole folder tree without asking. Recovery means a backup.
  • git add and git commit record changes. In a shared tree, a blanket add scoops up another agent's half-finished work and ships it. Memento's rules ban git add -A for exactly that.
  • git checkout and git restore can throw away uncommitted work permanently. Chapter 28, with the safety commit that goes first.
  • npm install downloads and runs other people's code and rewrites the lockfile. Never in a folder you are visiting. Chapter 19.

Inside MEMENTO you may use ls, cd, pwd, cat, head, open and later grep. Nothing else. Anything that writes goes in the book's sandbox folder, which exists to be broken.

WORDS YOU NOW OWN
Folder (directory)
A named container of files and other folders. The whole machine is one nest of them starting at /.
Path
The address of a file: the folders you walk through, joined with slashes.
Absolute and relative path
Absolute starts at / or ~ and means the same from anywhere. Relative starts from where you are standing.
Home folder
Your own top-level folder. ~ is shorthand for it. Yours is /Users/malikpeace.
Working directory
The folder the Terminal is standing in. pwd tells you, cd changes it.
Hidden file
A file whose name starts with a dot. Not secret, just not shown by default. Often the tooling that matters.
Editor
A program for a whole folder of code: file tree, project-wide search, go to definition, clickable path:line links.
WHERE TODAY'S ANALOGY BREAKS

Breaks when: you leave the Mac. On your iPhone there is no address you can type: each app gets a sealed container, which is why "where is my Memento data on my phone" has no path for an answer. A database row is not a file either. And on the disk a file is not one chunk of bytes in one spot, it is scattered pieces the operating system assembles for you. Real model: a path is a name the operating system agrees to resolve to some stored data, and how much of the machine is addressable that way is each operating system's choice. On a Mac, nearly all of it. On iOS, almost none. For this book, the building with rooms is the right picture.

RABBIT HOLE: why the slashes lean that way

Mac and Linux separate folders with /. Windows uses \, from a 1981 accident: the forward slash was already taken for command options, so paths got the backslash, and software has handled both ever since. Memento never meets the problem, since its files are only read by a browser or a Mac.
