HTML, CSS, and how a screen gets drawn

Every screen you have ever looked at in Memento is a tree of boxes with a stylesheet painted over it. Once you can see the tree, "the button is in the wrong place" stops being magic and becomes a thing with an address.

LAST TIME

JavaScript runs on one thread, so anything slow has to be handed off and waited for. await parks the current job and lets the thread keep serving taps, it does not freeze the phone. The queue is why a slow AI reply never locks the screen, and why the order of your log lines surprises you.

Quick check

You write a function and nothing happens. Why?
Writing a function defines it. Nothing runs until something calls it. Defining is the recipe card, calling is handing it to the cook.
Two names point at the same object and you change it through one. What does the other one see?
The change. Assignment copies the reference, not the object. That is chapter 11's aliasing bug and it is behind most "but I did not touch that" moments.
What does typeof cost you, and when should you reach for it?
Nothing, and immediately. The instant a value behaves strangely, ask it what it is. Text that looks like a number is the most expensive bug in the language.

The idea

Three separate things doing three separate jobs, smeared into one word: "the frontend".

HTML is the skeleton. What exists, and what is inside what. A heading, a button, a card with three things in it. No colours, no positions, no behaviour.

CSS is the skin. Colour, size, spacing, corner radius, blur. It never adds or removes anything, it dresses what HTML already declared.

The DOM is what the browser builds when it reads that HTML: a live tree of objects in memory. The file is a one-time instruction for building it. After that the file is history and the tree is the app. JavaScript changes the screen by changing the tree.

ANALOGY (TEMPORARY)

HTML is the architect's drawing. The DOM is the actual building, standing up, with people inside. CSS is the paint, the lighting, and the furniture. You cannot renovate a house by editing the drawing after it is built, and you cannot change a page by editing the HTML file while it is open. You walk into the building and move a wall. That is what document.querySelector is: walking in and finding the room.

The four words you need for HTML

An element is one node in the tree: an opening tag, contents, a closing tag. <button>Save</button>. Putting one element inside another is what makes it a tree. An attribute is extra information inside the opening tag, like type="button". Two of them matter most. An id is a unique name for one element and it is how JavaScript finds a specific thing. A class is a label you can stick on any number of elements and it is how CSS styles a whole category at once. That is the whole language for our purposes.

CSS in one screenful

A CSS rule has a selector saying who it applies to, then properties saying what to do to them. .chip means every element carrying that class, #app means the one element with that id, and each line inside the braces is one property.

Now the part that eats days. Several rules can hit the same element and disagree. The cascade is the tie-break: more specific wins, so an id beats a class and a class beats a tag name, and equal specificity means the later rule wins. This is why "I set the colour and nothing happened" is almost never a lie. The colour was set, then something more specific overruled it. A style that refuses to apply is a fight you lost, not a broken property.

The last CSS idea is the one Memento runs on. A custom property is a variable: --accent: #3ad9f5; declared once, then var(--accent) read in forty places. Change the one line and forty places move together. People call these design tokens.

How JavaScript touches the screen

Four moves cover most of what you will read.

MoveWhat it does
querySelector('#streak')Walks the tree and hands back the first element matching that CSS selector. Your way in.
textContent = '7'Replaces the words inside an element. The safe way to show data, because it can never be read as markup.
classList.toggle('done')Adds or removes a class, which lets CSS decide what that means. Behaviour in JS, appearance in CSS.
style.strokeDashoffset = '0'Sets one property directly on that one element. Wins every cascade fight, which is why it is a last resort.

Then events. When you tap, the browser makes an event object and offers it to the deepest element under your finger, then to that element's parent, then its parent, up to the document. That upward trip is bubbling. It is a feature, because one listener on a card can handle everything inside it, and a trap, because a button inside a tappable card fires both and the user gets two things at once. e.stopPropagation() is a handler saying "I dealt with this, do not pass it up". Memento's screens are cards inside cards, so it calls that constantly.

See it

These boxes render a real page in a throwaway frame, with console.log printing underneath. Predict, run, poke.

<h1 id="title">Streak: 0</h1> <button id="go">Add a day</button> <script> let streak = 0; var title = document.querySelector("#title"); document.querySelector("#go").addEventListener("click", function () { streak = streak + 1; title.textContent = "Streak: " + streak; console.log("changed the tree. streak is now", streak); }); </script>

Nothing rewrote the HTML. One node got new words and the browser repainted it. Now the same idea with the look left to CSS.

<style> .chip { display:inline-block; padding:10px 14px; border-radius:8px; border:1px solid #ccc; } .chip.done { background:#1fa32d; color:#fff; border-color:#1fa32d; } </style> <div class="chip" id="chip">Not done</div> <p><button id="t">Toggle</button></p> <script> var chip = document.querySelector("#chip"); document.querySelector("#t").addEventListener("click", function () { chip.classList.toggle("done"); chip.textContent = chip.classList.contains("done") ? "Done" : "Not done"; console.log("classes are now:", chip.className); }); </script>

The JavaScript never mentions green. It flips a label; the stylesheet decides what the label means. That separation is the whole reason CSS exists. Last one, bubbling:

<div id="card" style="padding:16px;border:1px solid #ccc;border-radius:12px"> the card itself (tap the grey area) <p><button id="inner">button inside</button> <button id="quiet">button that stops it</button></p> </div> <script> document.querySelector("#card").addEventListener("click", function () { console.log("CARD heard a click"); }); document.querySelector("#inner").addEventListener("click", function () { console.log("inner button heard it"); }); document.querySelector("#quiet").addEventListener("click", function (e) { e.stopPropagation(); console.log("quiet button heard it and kept it to itself"); }); </script>

Tap the inner button and two lines print, button first, then card. One tap, two handlers, because the event walked up. Tap the quiet one and only one line prints. That difference is the bug behind "why did it open twice".

Two ways to hear a tap, both live in Memento

The first is an inline handler: JavaScript written straight into an HTML attribute. Clarity's close button does it twice, click and the faster pointer event, so a tap never waits:

<button class="clarity-exp__close" id="clarityExpClose" aria-label="Back"
  onclick="smartCloseClarity(); return false;"
  onpointerdown="smartCloseClarity(); return false;">

The second is addEventListener, attached from JavaScript after the element exists. These are the summary tabs, and they are the whole chapter in eight lines: find elements, listen, stop the bubble, toggle classes, let CSS do the rest.

            const panels = scope.querySelectorAll('.ns-summary__panel');
            tabBtns.forEach(btn => {
              btn.addEventListener('click', (e) => {
                e.stopPropagation();
                const key = btn.getAttribute('data-tab');
                tabBtns.forEach(b => b.classList.toggle('is-active', b === btn));
                panels.forEach(p => p.classList.toggle('is-active', p.getAttribute('data-panel') === key));
memento-app/js/02-clarity-experience.js:472-479 (web pin ca8afc8)

That e.stopPropagation() is there because the tabs sit inside a fullscreen Clarity surface with its own tap handling. Without it, choosing a tab would also poke the surface behind it.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

Inline onclick is the older style: instantly readable, no wiring, and impossible to remove, replace, or double up later. addEventListener is the modern default, and you can attach several, remove them, and keep logic out of the markup. Memento uses both because the close button is one hard-coded control that will never need a second listener, while the tabs are built at runtime and cannot carry handlers in markup that does not exist yet. The bigger alternative is a framework that wires all of it for you, which is what the native rebuild bought. The cost here is that every listener is hand-attached and hand-removed, and a forgotten removal is a real leak.

Native cameo: no HTML at all

React Native has no browser and no DOM. It draws real iOS views, the same ones Apple's own apps use, so there is no cascade and no stylesheet file. The ideas survive as plain objects:

WORDS YOU NOW OWN
HTML
The skeleton. What exists on the page and what is nested inside what.
Element / attribute
One node in the tree / extra information written inside its opening tag.
id / class
A unique name for one element / a reusable label for many. JavaScript usually hunts by id, CSS usually styles by class.
CSS
The skin. Selectors pick elements, properties say what to do to them.
Cascade
The tie-break when rules disagree. More specific wins, then later wins. Most "my style did nothing" is a lost cascade fight.
Custom property
A CSS variable, written --name, read with var(--name). Memento's design tokens are these.
DOM
The live tree of objects the browser builds from your HTML. The file is the instruction; the tree is the app.
querySelector / textContent / classList
Find an element / replace its words / add and remove its labels. The three moves behind almost every screen update in Memento.
Event / bubbling
The object the browser makes when something happens / its trip up the tree from the deepest element to the document.
stopPropagation
A handler saying "I dealt with it, do not pass it up". Memento's defence against one tap firing two things.
Safe area inset
How much room the notch and home indicator steal, reported by the phone, read in CSS with env().
Inline handler / addEventListener
JavaScript written into an HTML attribute / a listener attached from code. Memento has both, on purpose.
WHERE TODAY'S ANALOGY BREAKS

Breaks when: the building rebuilds itself. A house stands still once built. The DOM gets torn down and re-raised constantly, hundreds of nodes at a time, every time a Memento module opens. The picture also implies the HTML file stays the truth. It does not. A second into a page's life the only truth is the tree in memory, and it can look nothing like the file. Real model: the DOM is mutable state that happens to be visible. Which raises the next chapter's question: if the screen is state you can edit directly, and your data is also state, what stops the two from disagreeing? Nothing, automatically. That is chapter 14.

RABBIT HOLE: why touching the tree too often makes a phone stutter

Reading a size out of the DOM, like offsetHeight, forces the browser to work out the layout right now. Writing marks it dirty. Alternate read, write, read, write in a loop and you force a full recalculation every pass. That is layout thrashing. The fix is boring: all the reads, then all the writes. Chapter 25 measures it.
