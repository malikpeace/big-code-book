Chapter 1 NEED ~45 min phone or Mac

The machine does exactly what you say

There is no mind inside the computer. It does not know what you meant. It does what you said, one tiny step at a time, at an absurd speed. Everything else in this book sits on that fact.

BEFORE WE START

You already run a software company. You approve plans, read status lines, and say "push it" every day. What you do not have yet is the picture of what is physically happening when you do. This chapter gives you the bottom layer of that picture. Nothing to install, nothing to type. Just read and press Run a few times.

Quick check

No earlier chapters yet, so three questions about you.

When you tap a button in Memento, where do you currently think the work happens?
Whatever you answered, hold it. By the end of chapter 2 you will be able to say exactly which parts happen on the phone and which parts happen on a computer you have never seen.
What do you think a "program" physically is?
A file. Text, saved on a disk. When it runs, the text becomes instructions a chip follows. This chapter shows that.
Do you think the computer understands what you want?
It does not. Not even a little. The AI agent you talk to does guess what you want. The machine underneath it does not. Keeping those two apart is the whole chapter.

The idea

A computer is three things and a loop.

The CPU is a chip that can do a small number of stupid things: add two numbers, copy a number from here to there, compare two numbers, jump to a different instruction. That is roughly it. It does one of those things, then the next, then the next. Billions of times a second.

Memory is a huge row of numbered slots. Each slot holds a number. The CPU reads from slots and writes to slots. When the power goes, the slots are wiped.

The disk is where things survive the power going. A file is a named chunk of bytes on the disk. Your code is a file. A photo is a file. Memento's JavaScript is 38 files.

A program is a file full of instructions. When you run it, the instructions get copied into memory, and the CPU starts at the first one and walks forward. A program that is currently running is called a process. Memento open in Safari is one process. The server that answers it, on a computer in a data centre, is a different process.

ANALOGY (TEMPORARY)

The CPU is a very fast, very obedient intern who cannot think. Memory is the intern's desk: a row of numbered sticky notes. The disk is the filing cabinet across the room. A program is a to-do list you leave on the desk. The intern reads line 1, does exactly that, reads line 2, does exactly that. If line 7 says "put the coffee in the bin", the coffee goes in the bin. The intern never asks "are you sure?" The intern never notices that you obviously meant the cup.

Here is the part that matters. The CPU has no idea what a "goal" or a "streak" or a "user" is. It moves numbers between slots. A streak of 12 days is the number 12 sitting in a slot. "Show the streak on screen" is a few thousand instructions that end with numbers being written into a special region of memory that the screen is wired to read from. Every meaning is in the human's head. The machine has none.

This is why software breaks. You wrote "if the streak is bigger than 7, show the badge" but the streak got saved as the text "7" instead of the number 7, and comparing text to a number does something you did not expect. You meant one thing. You said another. The machine did the other. Forever. At full speed.

Where your AI agents fit

This is the single most important idea in the book for you specifically, so read it twice.

When you tell Codex or Fable "make the streak badge show after a week", the agent guesses what you mean. It reads your app, infers "a week" is 7 days, picks a file, writes instructions. That guessing is real and it is often good. But the agent is a writer, not the machine. Once the instructions are written, the machine runs them literally. If the agent guessed wrong, or wrote a typo, or misread a number, the machine does not catch it. The machine does not know what you meant either. There is no layer where intention lives. Only text, and a chip that obeys it.

So there are two very different questions, and you have been mixing them:

  • Did the agent understand me? A question about a guess. You check it by reading the plan and the change.
  • Does the code do what it says? A question about literal instructions. You check it by running it and looking.

Vibe coding is skipping both questions. This book is the opposite.

See it

Five tiny programs. For each one, say out loud what you think it will print before you press Run. Being wrong is the point. Every wrong guess is a place where your model of the machine differs from the real machine, and that is exactly the gap we are closing.

You do not need to understand the words yet. console.log means "print this". Chapter 9 teaches the rest.

// 1. The machine does the steps in order. Nothing else. console.log("first"); console.log("second"); console.log("third");
// 2. It does not know what you meant. It knows what you said. // You meant "add these numbers". What did you say? console.log(7 + 5); console.log("7" + "5"); console.log("7" + 5);
// 3. A name tag is not the thing. Change the thing, the tag shows the change. let streak = 3; console.log(streak); streak = streak + 1; console.log(streak); // Now: what does the NEXT line print? Guess first. console.log(streak > 3);
// 4. The machine will happily do something pointless a million times. let count = 0; for (let i = 0; i < 1000000; i++) { count = count + 1; } console.log(count); console.log("that took almost no time");
// 5. And it will do something wrong forever, at full speed. // This loop never ends. The sandbox kills it after 3 seconds. // Press Run. Read the message. That message is what a real bug feels like. let n = 0; while (n < 10) { console.log("n is", n); // the human forgot to change n. The machine does not notice. }

Number 2 is the one people remember. 7 + 5 is 12. "7" + "5" is "75", because the quotes make them text, and adding text glues it together. "7" + 5 is also "75", because the machine picks a rule and applies it without asking. Real bugs in real apps come from exactly this: a number that arrived as text.

Now in Memento

ANY APP

Every app is a pile of files on a disk, loaded into memory, walked through by a CPU. A "feature" is a region of that pile. Deleting a feature means deleting files, and every place that still names the deleted thing becomes an instruction the machine cannot follow. The machine does not know the feature is gone. It just hits a name that points at nothing, and stops.

MEMENTO

The best specimen in the whole codebase is a file that exists only because the machine is literal. In v1319 the old Action module, 6,070 lines, was deleted. About eighty other places in the app still say ActionExperience.open(). If that name vanished, each of those eighty spots would crash the moment a user touched it. So a human left a 37-line file whose only job is to catch the old name and forward it to the new system:

const ActionExperience = {
  // the old module never opens, so nothing may believe it is open
  isOpen: false,
  pageWrap: null,

  // every legacy door lands in the real flow
  open() {
    try {
      if (window.ActionFlow && typeof ActionFlow.start === 'function') return ActionFlow.start();
    } catch (e) {}
  },

  // the old surfaces are gone; these exist so old callers stay harmless
  init() {},
  close() {},
  render() {},
  renderContent() {}
};
memento-app/js/33-action-shim.js:20-37 (web pin ca8afc8)

Read the comments above the code in that file some time. Twenty of its 37 lines are a human explaining to future humans why the machine needs this. The machine does not read comments. Only people do.

THE ALTERNATIVE, AND WHY MEMENTO CHOSE THIS

The clean alternative is to edit all eighty call sites to say the new name, then delete the shim. That is more correct and more work, and with two agents editing in parallel it risks a half-done rename where forty spots say the new name and forty say the old one. The shim is a deliberate, documented piece of debt: cheap now, a small tax on understanding later. Chapter 26 comes back to it as the textbook example of debt done honestly.

WORDS YOU NOW OWN
CPU
The chip that does the work. Reads one tiny instruction, does exactly that, reads the next. No understanding anywhere in it.
Memory (RAM)
Numbered slots holding numbers. Fast. Wiped when power goes.
Disk and file
Where things survive. A file is a named chunk of bytes. Code is files.
Program and process
A program is a file of instructions. A process is that program while it is running.
Literal execution
The machine does what the text says, not what the author meant. Every bug lives in that gap.
WHERE TODAY'S ANALOGY BREAKS

Breaks when: you picture one intern. A phone's CPU has several cores, each walking its own list at the same time, and the screen, the radio, and the disk each have their own small chips doing their own work. Also, a real CPU reorders and predicts instructions for speed, so "one step at a time" is a story the chip tells you, not what it literally does inside. Real model: a process is a sequence of instructions executed with the appearance of order; the hardware guarantees the result looks as if it ran one step at a time. For everything in this book, "one obedient step at a time" gives you the right answers. Chapter 12 adds the one place where the order gets interesting: waiting for the network.

RABBIT HOLE: what an instruction physically is

An instruction is a number. The CPU's designers publish a table: this number means "add", that number means "copy". Your JavaScript never becomes those numbers directly; a program called an engine (V8 in Chrome, JavaScriptCore in Safari) reads your text and produces them on the fly. That is why JavaScript works on an iPhone and a Mac despite the chips being different: the engine on each does the translating. Chapter 3 has the history of how humans stopped writing the numbers by hand.
